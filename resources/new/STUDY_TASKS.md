# 每日挑战、卷王悬赏与三级提示

## 使用方式

大厅上方「每日挑战」和学习档案里的挑战入口都能打开咪咪冒险地图。原「学习现场已保留」重复入口已移除。任务使用猫咪、寻宝路标、宝箱奖励与达成印章，包含每日、每周、卷王挑战、每日记录四个分类，沿用全局四季主题。学习页不新增任务导航，保持答题专注。

| 周期 | 完成整句数 | 额外小鱼干 |
| --- | --- | --- |
| 每日 | 1 / 10 / 20 | 5 / 20 / 35 |
| 每周 | 10 / 50 / 100 | 25 / 80 / 160 |
| 卷王每日 | 50 / 100 / 200 | 120 / 350 / 900 |
| 卷王每周 | 100 / 300 / 500 | 200 / 800 / 1600 |

达到目标自动发奖，可同时达成多个目标。每日按北京时间零点刷新，每周一开始新周期。多阶段题只在最后阶段检查通过后记一次；不计分复习、直接解锁完整答案的题不计任务；同一关当天去重。

普通通关弹窗只显示单题奖励。点击下一关或再次重温时，如有任务达成，会先显示独立挑战庆祝，再执行原选择。多个目标在同一题达成时合并为一次挑战庆祝；两段庆祝分别播放「小成功」和「惊喜完成」音频，遵守全局音量与静音。挑战音效使用已有 reward 音效槽。奖励在答对时已到账，庆祝按钮不再次发奖。

普通与卷王奖励按不同任务 ID 叠加。新卷王目标沿用已有记录，旧记录已达标但尚未发放的卷王奖励，会在下一次有效整句通关时核算。

学习记录保留每个日期的关卡 ID，不从旧的累计成绩推测历史完成时间；默认显示本周图表与最近 14 天，更早记录可以翻页查看。

## 存档

复用现有 `collection` 快照，新增可选 `studyTasks` 字段：

- `startedOn`：开始记录的日期；
- `days`：日期 → 当天已完成的关卡 ID；
- `grants`：周期日期 + 任务 ID → 已发放的小鱼干。

每次成功通关的单次 collection 更新同时写入记录、发奖标记及余额，避免因渲染或重复提交重复发奖。使用原有完整快照同步和账号冲突处理；旧存档不带此字段仍正常加载。无新数据库表、服务端接口或环境变量。新增格式校验位于 [snapshot.mjs](shared/snapshot.mjs)。

此功能沿用现有本地学习与小鱼干模型，不改变好友恶作剧道具的服务端有效题目验证。

## 提示

第一次打开提示显示当前阶段中文目标、结构说明及实际出现的词组／常用表达的中文意思，并计作第 1 次提示。

第 2、3 次各补入第一个空格的正确词块，从待选区取出，或将轨道中错位的同一词块移动到该空格。保留所有真实词块 ID，不替换其他已填词块；满轨道时不会消耗一次补词提示。重复单词按独立词块处理。

保留原有降低单题奖励及第三次提示后的完整答案选项。词组表由 [phraseHints.ts](src/utils/phraseHints.ts) 集中管理，只匹配当前阶段实际出现的英文。目前 1190 题均有匹配，不依赖 AI 请求或密钥。

npm run test:cloud
npm run test:social
npm run test:rail

浏览器测试使用 Playwright，可通过 `PLAYWRIGHT_MODULE` 指向已有安装。UI 测试启动隔离的真实云服务与临时 SQLite，覆盖提示、双段庆祝与音频播放、普通／卷王叠加奖励、刷新、跨设备云恢复及 320/390/1360 宽度，结束后删除测试数据。

GitHub Pages 发布新的构建产物即可。自建服务器需要更新当前源码（包含 `shared`）并重新构建／替换容器，沿用原环境文件与数据卷，不删除数据卷；无需数据库迁移或配置新密钥。
