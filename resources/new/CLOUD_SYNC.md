# 英语拼块：账号与云端同步

## 已实现

- 游戏顶部“云账号与同步”，或设置中的同名入口。
- 账号注册、登录、退出；账号名为 4–32 位字母/数字/下划线，密码 10–128 位。密码经随机盐和 scrypt 派生后存储；服务端仅保存会话令牌的 SHA-256 摘要，会话有效期 30 天。
- 每个账号独立存档：学习进度、错题、收藏词、计时成绩、小鱼干、猫咪收藏/装扮，以及通用音频偏好。
- 同一浏览器多个标签页中，有标签页修改记录或切换账号时，其余标签页暂停同步并提示刷新，避免旧内存状态覆盖新记录。
- 首次登录/换账号必须选择上传本机或采用云端；不自动上传其他账号留在本机的记录。
- 在线每 5 秒同步，返回前台或恢复网络时重试；无网络可继续本机游玩。未完成句子的临时词块位置不上传。
- 同时修改时暂停并显示选择；使用数据库事务和版本号进行比较更新，绝不把两台设备的小鱼干相加。离线会话或过期登录不会清除本机记录。
- 覆盖本机前保留最近 3 份本机回退备份；可恢复、下载和导入。恢复后暂停自动上传，重新选择同步方向。
- 服务端每账号保留最近 30 个历史版本，可通过带身份验证的 `/api/cloud/history`、`/api/cloud/history/:revision` 读取。数据库位于持久化数据目录。
- 旧无账号 `/api/lan-save` 不再用于网页或 EXE 自动同步。原本机 localStorage、Electron 磁盘备份和旧 LAN 文件不清除。

自定义上传的 MP3/WAV、设备专属朗读声音、布局编辑数据仍只留在本机；它们不在本阶段云同步范围。完整游戏备份功能继续保留。内置音乐随网页/EXE 提供。

## 本地运行与预览

需要 Node.js 24 或更新版本。

```bash
npm install --package-lock=false
npm run dev
```

开发服务器也提供云账号接口。手机与电脑打开同一个可访问的网页地址，登录同一账号，即可验收同步。Codespaces 是开发预览，不能代替长期在线托管；停止 Codespace 后该预览同步服务也停止。

开发数据库默认写入 `cloud-data/accounts.sqlite`，该目录不进入 Git，不会随前端构建复制到 dist。不要把数据库、旧 sync-data 或 .env 放进公开静态目录。

## 正式部署：Node 服务

1. 准备有持久化磁盘的服务器和 HTTPS 域名。
2. `npm run build`。
3. 配置环境变量后运行 `npm start`，由 HTTPS 反向代理把域名转发到 3000 端口。

```text
PORT=3000
CLOUD_DATA_DIR=/你的持久化目录/englishblocks
CLOUD_ALLOWED_ORIGINS=englishblocks://app
CLOUD_ALLOW_REGISTRATION=true
```

网页与接口同源部署时，`VITE_CLOUD_URL` 留空；前端会使用当前网站地址。若前端独立托管，构建前把 `VITE_CLOUD_URL` 设为 API 所在 HTTPS 源，并把网页的精确来源加入服务端 `CLOUD_ALLOWED_ORIGINS`，多个来源用逗号分隔。

不要在 VITE_ 变量中放数据库密码、会话密钥等秘密；它们会被编译进客户端。账号服务使用数据库中的随机会话令牌，不需要向前端分发数据库凭据。

服务仅处理账号授权的存档，不接受 URL 中指定其他用户 ID。默认不信任代理转发 IP；如需按真实来源限流，可用 `CLOUD_TRUST_PROXY` 明确列出可信代理 IP/网段。未配置时，反向代理后面的登录请求会共享代理 IP 的限流额度。

账号不依赖邮箱服务，目前不包含邮件验证、忘记密码邮件、付费/防作弊经济系统。需要开放公开运营时可继续接入账户恢复、邮件与运营管理。

## Docker + HTTPS 示例

仓库提供 Dockerfile 和 `deploy/compose.yaml`。把域名 DNS 指向服务器，服务器允许 80/443 入站：

```bash
GAME_DOMAIN=你的真实域名 docker compose -f deploy/compose.yaml up -d --build
```

数据库在 `game-data` 持久卷中，重建容器保留。只重建镜像不会把本地开发数据库上传至正式环境。本会话没有执行公网部署或 Docker 镜像构建。

备份服务器时应停止 game 服务后备份完整持久卷（SQLite 主文件及其日志），或使用 SQLite 的一致性备份工具；不要在运行中只拷贝主数据库文件。保留多份异地备份。重新部署时挂回原持久卷。

## Windows EXE

在 Windows 打包前设置实际云地址：

```powershell
$env:VITE_CLOUD_URL="https://你的正式域名"
npm run desktop:package
```

EXE 从配置的 HTTPS 地址直接访问账号 API，服务端允许 `englishblocks://app` 来源；不再连接 `127.0.0.1:3000`。本机固定来源和磁盘存档仍保留。没有配置云地址的安装包仍能本机游玩，云窗口会提示尚未配置。现有旧 EXE 不会自行获得这次修改，需要重新构建并替换。

## 验证

```bash
npm run lint
npm run build
npm run test:cloud
npm run test:rail
npm run test:timing
```

`tests/cloud-server.test.cjs` 在临时目录使用隔离数据库，覆盖账号隔离、并发 CAS、历史版本、非法数据、会话过期、注销、来源检查和登录限流。

`previews/check-cloud.cjs` 使用两套独立浏览器存储模拟电脑与手机，并运行独立临时云服务，不读取真实开发账号数据库。

## 本次验证结果

类型检查、生产构建、4 组账号服务集成测试、轨道压力测试和计时回归测试均通过。正式服务启动检查验证了编译网页、账号接口、数据库隔离和旧无账号接口停用；Docker Compose 配置校验通过，未构建/部署容器。

浏览器使用独立的电脑/手机存储与临时数据库，验证了首次选择、跨设备通关/奖励/音量同步、离线重连、双端冲突、覆盖前回退备份、账号刷新恢复、退出保留本机进度，以及同浏览器其他标签页更新时暂停旧标签上传。测试资源按设备依次释放后，刷新及多标签测试通过。没有使用真实学习存档做通关测试。

当前 Codespaces 预览已接入账号接口，可供手动验收。尚未部署长期在线服务器、未接入实际域名，也未生成或在 Windows 实机验证新版 EXE。要完成正式上线，需要选定服务器/托管平台、持久化数据盘和 HTTPS 域名，再按上面的 Windows 云地址配置重新打包。
